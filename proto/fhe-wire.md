# FHE columns — wire and cryptographic specification (protocol v2 extension)

Normative for every driver. Test vectors: `fhe-vectors.json` (generated by the Python reference,
re-verified by `tests/test_fhe.py::test_published_vectors`). Prose: `../docs/fhe-columns.md`.

## Curve and encodings
* Curve BN254 = `alt_bn128` (EIP-197): field `p = 0x30644e72e131a029b85045b68181585d97816a916871ca8d3c208c16d87cfd47`,
  group order `n = 0x30644e72e131a029b85045b68181585d2833e84879b9709143e1f593f0000001`.
  G1 = (1, 2). G2 generator as in EIP-197 (x = x0 + x1·i, y = y0 + y1·i, i² = −1):
  x0 = 10857046999023057135944570762232829481370756359578518086990519993285655852781,
  x1 = 11559732032986387107991004021392285783925812861821192530917403151452391805634,
  y0 = 8495653923123431417604973247489272438418190587263600148770280649306958101930,
  y1 = 4082367875863433681332203403145435568316851327593401208105741076214120093531.
* **G1 point**: 64 bytes = x‖y, 32-byte big-endian affine coordinates; all-zero = infinity.
* **G2 point**: 128 bytes = x0‖x1‖y0‖y1 (each 32-byte big-endian); all-zero = infinity.
* **Valid point**: coordinates < p, on the curve (G2: on the twist `y² = x³ + 3/(9+i)`), and in the
  prime-order subgroup (mandatory for G2 from untrusted input; the Python/py_ecc path checks only the
  curve equation, the native path checks both).
* **GT element**: 384 bytes = 12 big-endian 32-byte coefficients `c0…c11` of the py_ecc polynomial
  basis `Σ cm·w^m` with `w^12 = 18·w^6 − 82` (so `i = w^6 − 9`).

## Scheme (secret `s ∈ [1, n)`, public `Q = s·G1`, `Q2 = s·G2`; plaintext `v ∈ Z`, |v| ≤ range)
```
Enc(v):  r1, r2 ←$ [1, n)
         C1 = r1·G1        C2 = v·G1 + r1·Q          (G1 half)
         D1 = r2·G2        D2 = v·G2 + r2·Q2         (G2 half) — r1 and r2 INDEPENDENT (mandatory)
cell    = C1 ‖ C2 ‖ D1 ‖ D2                                       384 bytes
```
* `SUM` blob (128 bytes) = Σ C1 ‖ Σ C2 over the chosen cells, optionally both multiplied by a public
  scalar k (EC scalar multiplication). Decrypt: `M = ΣC2 − s·ΣC1 = (k·Σv)·G1`, then a bounded
  discrete log of `M` w.r.t. G1 over `[−range', range']` (baby-step/giant-step).
* `DOT` blob = `tag(1 byte) ‖ c00 ‖ c01 ‖ c10 ‖ c11` (4 × 384 bytes GT), where for each row
  `(a_i, b_i)` the server forms the **ciphertext product ★_ct** (a pairing, not a scalar multiplication)
  `c00 = Π e(D1(a_i), C1(b_i))`, `c01 = Π e(D1(a_i), C2(b_i))`, `c10 = Π e(D2(a_i), C1(b_i))`,
  `c11 = Π e(D2(a_i), C2(b_i))` (e: G2 × G1 → GT). Tag `0x01` = py_ecc optimal-ate, `0x02` = native mcl
  optimal-ate; the two pairings differ by a fixed exponent, so each has its own GT generator
  `g = e(G1, G2)` (published in `fhe-vectors.json` → `gt_generators`).
  Decrypt: `M = c11 · c01^(−s) · c10^(−s) · c00^(s²) = g^(Σ a_i·b_i)` then a bounded discrete log w.r.t. `g`.
  Partial blobs of the same tag combine by component-wise GT multiplication.
* Integrity tags (optional, `authenticated`): hidden column `__fmac__<col>` holds `Enc_scalar(α·v + γ)`
  (same cell layout, scalar mod n, no range limit). `α = PRF("alpha") or 1`, `γ = PRF("gamma", table, col, rowid)`,
  `PRF(label, *parts) = HMAC-SHA512(HMAC-SHA256(secret_bytes, "torussql/fhe/" + label), "\0".join(str(p)))` mod n,
  `secret_bytes` = `s` as 32 big-endian bytes. Check for rows I and multiplier k:
  `(ΣC2' − s·ΣC1') == α·(ΣC2 − s·ΣC1) + k·(Σ_{i∈I} γ_i)·G1` (group elements, no discrete log needed). The tag of a
  new row is written right after INSERT (the row id is only then known), inside one transaction.

## RPCs (JSON over the framing of wire v2; binary values are `{"t":"x","v":"<base64>"}`)
| method | args | result |
|---|---|---|
| `insert` / `update_cell` | a cell (and `__fmac__<col>`) for an FHE column | — |
| `plain_cells` | `[table, col, ids]` (also `__fmac__<col>`) | list of binary values |
| `fhe_sum` | `[table, col, ids, k?]` (col may be `__fmac__<col>`; ≤ 5000 ids) | base64 SUM blob |
| `fhe_dot` | `[ltable, lcol, lids, rtable, rcol, rids, backend?]` (≤ 300 ids pyecc / 6000 mcl) | base64 DOT blob |

Column policy is `fhe` (`INT` only). The server accepts only valid 384-byte cells in FHE columns and never
binary values elsewhere. Clients must chunk requests below the caps and combine partial blobs themselves.
